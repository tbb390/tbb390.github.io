一、科一：学生观（选择题高频）

1. 学生是发展中的人

  • 学生具有发展的潜能和可能性，教育要用发展的眼光看待学生。
  • 学生的发展具有动态性，不应固定评价学生。

    • 2. 学生是独特的人

  • 每个学生具有自身的兴趣、特点和发展差异。
  • 教育应尊重个体差异，做到因材施教。

    • 3. 学生是具有独立意义的人

  • 学生是学习活动的主体，具有主观能动性。
  • 教育应尊重学生主体地位，促进自主发展。

    • 4. 学生身心发展规律

  • 顺序性：教育要循序渐进。
  • 阶段性：教育要根据不同年龄特点开展。
  • 不平衡性：教育要抓住关键期。
  • 个别差异性：教育要因材施教。

    • 5. 教育共同发展

  • 教师与学生是共同成长、共同发展的关系。
  • 教学过程是师生互动、教学相长的过程。

    • 二、科二：新课程改革

    简述新课程改革的课程结构

  • 整体设置九年一贯的义务教育课程。
  • 小学阶段以综合课程为主。
  • 初中阶段设置分科与综合相结合的课程。
  • 高中阶段以分科课程为主。
  • 从小学至高中设置综合实践活动课程并作为必修课程。

    • 简述新课程改革背景下的评价观

  • 评价目的：促进学生发展。
  • 评价主体：评价主体多元化，教师、学生、家长共同参与。
  • 评价内容：评价内容综合化，不仅关注知识成绩，也关注能力、情感态度。
  • 评价方式：评价方式多样化，形成性评价与终结性评价结合。
  • 评价功能：由选拔功能转向发展功能。

    • 三、教学概述

    我国现阶段的教学任务

  • 首要任务：使学生掌握系统的科学基础知识和基本技能。
  • 发展学生智能，特别是培养创新能力和实践能力。
  • 发展学生体力，促进身体健康。
  • 培养科学世界观、思想品德、审美情趣和心理素质。

    • 教学过程的结构

  • 引发学习动机：教学过程的起始阶段。
  • 领会知识：教学过程的中心环节。
  • 巩固知识。
  • 运用知识。
  • 检查知识。

    • 四、教学评价

    教学评价的基本原则及落实要求

  • 客观性原则：评价标准客观公正，避免主观偏差。
  • 发展性原则：评价促进学生发展，而非单纯筛选。
  • 整体性原则：全面评价学生知识、能力和素质。
  • 指导性原则：评价结果用于改进教学。

    • 教学评价的作用（功能）

  • 诊断功能：了解学生学习情况，发现问题。
  • 激励功能：调动学生学习积极性。
  • 调节功能：调整教学内容和方法。
  • 教学功能：促进学生学习和教师教学改进。
  • 鉴定功能：判断教学效果和学生发展水平。

    • 相对性评价与绝对性评价区别

  • 相对性评价：以学生群体平均水平或排名作为标准，比较学生之间差异。
  • 绝对性评价：以预定教学目标作为标准，判断是否达到要求。

    • 核心区别： 相对评价看“人与人之间比较”，绝对评价看“是否达到目标”。

    形成性评价与终结性评价区别

  • 形成性评价：教学过程中进行，用于发现问题、改进教学。
  • 终结性评价：教学结束后进行，用于判断学习成果。

    • 核心区别： 形成性评价重过程改进，终结性评价重结果判断。

    五、教学组织形式

    教学组织形式选择依据

  • 教学目的和任务。
  • 课程性质和教学内容特点。
  • 学生数量、年龄特点和学习基础。
  • 教学时间、教学设备和环境条件。
  • 教师自身能力和教学经验。

    • 教学组织形式类型

  • 班级授课制：教师面向全班学生进行教学，是现代学校基本组织形式。
  • 个别教学：根据学生个体差异进行教学。
  • 分组教学：按照学生特点组成不同小组开展教学。
  • 复式教学：教师在同一时间内对两个或多个年级学生进行教学。

    • 本节总结

    复习科一学生观以及科二新课改、教学过程、教学评价和教学组织形式相关高频考点。重点掌握选择题中的概念对应关系，以及简答题中的课程结构、评价观、教学任务、教学过程结构和教学评价分类。

    🤖 智能生态与智能协同系统设计要点

    一、智能生态：Agent能力建设核心

    智能生态关注的是 Agent 如何稳定、安全地调用外部能力，重点不是单纯连接工具，而是保证工具调用的完整闭环。

    核心关注四个方面：

  • 接口规范： 统一工具输入输出格式，明确接口协议、参数类型和返回结构，保证模型能够正确理解和调用。
  • 权限控制： 明确不同工具、数据和操作的访问范围，避免 Agent 超权限执行。
  • 安全机制： 包括身份认证、数据保护、操作审计、高风险操作确认等，保证系统可控。
  • 返回值质量： 关注工具执行结果是否准确、完整、可被模型继续理解和利用，提高任务成功率。

    • 工具设计需要关注：

  • 工具描述是否清晰： 模型是否能够理解工具作用、适用场景和调用条件。
  • 参数定义是否完整： 明确参数名称、类型、格式、是否必填以及约束条件。
  • 权限设计是否合理： 不同工具能力需要对应不同权限等级，避免风险操作直接执行。
  • 实际成功率： 不仅看接口是否能调用，还要看 Agent 在真实任务中的完成效果。

    • 二、智能协同（UCLAW）：跨设备Agent执行流程

    智能协同主要解决 Agent 如何连接远程设备、系统和第三方服务，并完成任务执行闭环。

    涉及环境：

  • 远程设备。
  • 网络环境。
  • 第三方服务。
  • 操作系统和应用服务。

    • 执行链路：

  • 环境接入： 需要明确进入 OS 的账号信息、网络配置、端口开放情况以及服务状态。
  • 设备绑定： 建立 Agent 与目标设备之间的可信连接关系。
  • 任务下发： 将用户需求转换为具体执行任务，并发送到目标设备。
  • 权限确认： 执行敏感操作前需要验证权限，必要时进行人工确认。
  • 执行日志： 记录任务执行过程，包括调用工具、执行命令、异常情况等。
  • 结果回传： 将执行结果返回 Agent，并用于下一步决策或反馈用户。

    • 三、模型选择考虑因素

  • 任务复杂度： 简单问答可选择轻量模型，复杂推理、多步骤Agent任务需要更强推理能力模型。
  • 上下文长度： 需要处理大量文档、代码或历史信息时，需要支持长上下文模型。
  • 工具调用能力： Agent场景需要模型具备稳定的Function Calling / Tool Calling能力。
  • 响应速度： 实时交互场景需要考虑推理延迟和吞吐能力。
  • 成本： 综合考虑调用次数、Token消耗和部署成本。
  • 部署环境： 涉及企业内部数据时，需要考虑本地部署、私有化部署以及数据安全要求。

    • 总结

    智能生态重点关注“工具能力是否标准、安全、可靠”；智能协同重点关注“跨设备任务执行是否形成完整闭环”。一个成熟Agent系统需要具备能力接入、权限控制、任务规划、执行记录和结果反馈的完整链路。
