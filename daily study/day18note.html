📖 os

操作系统期末复习笔记

第一章 操作系统引论

  • 操作系统定义
    • 操作系统（OS）是管理计算机硬件和软件资源的软件。
    • 是用户与计算机硬件之间的接口。
    • 操作系统位于用户与硬件之间。
  • 操作系统发展过程
    • 无操作系统
    • 单道批处理系统
    • 多道批处理系统（操作系统成熟标志）
    • 分时系统
    • 实时系统
  • 分时系统特点
    • 多路性：多个用户同时使用系统。
    • 独占性：用户感觉独占主机。
    • 及时性：短时间内获得响应。
    • 交互性：边运行边操作程序。
    • 考试重点：交互性。
  • 实时系统特点
    • 在规定时间内完成任务。
    • 广泛用于工业控制、航空航天等领域。
    • 考试重点：及时性。
  • 操作系统四大特征
    • 并发性（最重要）
    • 共享性
    • 虚拟性
    • 异步性
  • 并发与并行
    • 并发：多个任务在同一时间段内交替执行。
    • 并行：多个任务在同一时刻同时执行。
    • 记忆：并发是假同时，并行是真同时。
  • 共享性
    • 多个进程共同使用系统资源。
    • 并发与共享互为存在条件。
    • 没有并发就没有共享。
  • 操作系统五大功能
    • 进程管理（管理CPU）
    • 存储管理（管理内存）
    • 设备管理（管理I/O设备）
    • 文件管理（管理文件）
    • 用户接口（人机交互）
  • 第一章考试速记
    • 成熟标志：多道批处理系统。
    • 分时系统重点：交互性。
    • 实时系统重点：及时性。
    • 四大特征：并发、共享、虚拟、异步。
    • 五大功能：进程、存储、设备、文件、接口。

第二章 进程管理（第一部分）

  • 进程（Process）
    • 进程是程序的一次执行过程。
    • 进程是资源分配和调度的基本单位。
    • 每个进程拥有唯一PID（进程标识符）。
  • 程序与进程区别
    • 程序是静态的，进程是动态的。
    • 程序长期保存在外存，进程具有生命周期。
    • 程序不是资源分配单位，进程是资源分配单位。
  • 进程组成
    • PCB（进程控制块）
    • 程序段
    • 数据段
  • PCB（Process Control Block）
    • PCB是进程存在的唯一标志。
    • 操作系统通过PCB管理进程。
  • PCB主要内容
    • 进程标识符PID
    • 进程状态信息
    • 程序计数器PC
    • 寄存器信息
    • 资源分配信息
  • 程序计数器（PC）
    • 记录下一条即将执行的指令地址。
    • CPU依靠PC实现程序顺序执行。
  • 进程特征
    • 动态性（最基本特征）
    • 并发性
    • 独立性
    • 异步性
  • 进程三种基本状态
    • 运行态（Running）—— 正在占用CPU。
    • 就绪态（Ready）—— 已具备运行条件，只缺CPU。
    • 阻塞态（Blocked）—— 等待某事件发生。
  • 状态转换
    • 就绪 → 运行：获得CPU。
    • 运行 → 就绪：时间片用完。
    • 运行 → 阻塞：请求I/O或等待资源。
    • 阻塞 → 就绪：I/O完成或资源到达。
  • 进程控制原语
    • 创建原语：建立PCB，创建进程。
    • 撤销原语：终止进程并回收资源。
    • 阻塞原语：运行态→阻塞态。
    • 唤醒原语：阻塞态→就绪态。
  • 原语特点
    • 执行过程不可中断。
    • 具有原子性。
    • 通常通过关中断实现。
  • 进程切换（Context Switch）
    • 保存当前进程运行现场。
    • 选择新的进程运行。
    • 恢复新进程运行环境。
    • 本质：保存现场 + 恢复现场。
  • 第二章前半部分考试速记
    • PCB是进程存在的唯一标志。
    • 动态性是进程最基本特征。
    • 就绪态：除CPU外资源全部满足。
    • 阻塞态不能直接获得CPU。
    • 运行→阻塞：等待I/O。
    • 阻塞→就绪：I/O完成。
    • 原语执行不可中断。
    • 进程切换：保存现场 + 恢复现场。
💡ragent

📅 Ragent 学习记录（Prompt → LLM → SSE）

Prompt 阶段

  • Retrieval 负责检索资料，不负责生成答案。
  • 系统会收集 Question、Memory、KB Context、MCP Context。
  • 所有上下文统一进入 PromptContext。

RAGPromptService

  • 负责组织上下文并生成最终 Prompt。
  • 根据场景选择对应 PromptTemplate。

PromptTemplate

  • 定义 Prompt 格式。
  • 常见场景：KB、MCP、KB+MCP、System。
  • RAGPromptService 负责向模板填充数据。

Memory 管理

  • Memory 最终会进入 Prompt。
  • 保留最近几轮对话。
  • 历史内容通过 Summary 压缩。
  • 最终以「摘要 + 最近对话」形式参与生成。

LLMService

  • 模型调用统一入口。
  • 负责发起 streamChat 请求。

RoutingLLMService

  • 负责模型路由。
  • 支持多模型选择、降级和切换。

ChatClient

  • 真正调用模型 API 的组件。
  • 负责发送 HTTP 请求并接收模型返回。
  • 屏蔽不同模型厂商接口差异。

Streaming

  • 模型按 Token 流式生成内容。
  • 用户无需等待完整回答生成。

SSE

  • Server-Sent Events，服务器主动推送消息。
  • 适用于大模型流式输出场景。

SseEmitterSender

  • 基于 Spring SseEmitter 的业务封装。
  • 负责将模型生成的 Token 实时推送给前端。
🤔 概率

📚 第一章：概率论基本概念（重点公式）

  • 概率加法公式
    P(A∪B)=P(A)+P(B)-P(AB)
  • 概率乘法公式
    P(AB)=P(A)P(B|A)
  • 条件概率
    P(B|A)=P(AB)/P(A)，其中 P(A)>0
  • 完备事件组
    A₁,A₂,...,Aₙ两两互斥，且A₁∪A₂∪...∪Aₙ=Ω。
  • 全概率公式
    当A₁,A₂,...,Aₙ构成完备事件组时：
    P(B)=ΣP(Aᵢ)P(B|Aᵢ)
  • 贝叶斯公式
    P(Aᵢ|B)=P(Aᵢ)P(B|Aᵢ)/P(B)
  • 划分思想
    遇到“来源不明确”的问题，优先寻找完备事件组进行划分，再使用全概率或贝叶斯公式求解。
  • 典型题型
    三个厂家、三条生产线、三家医院等来源分类问题。
📌agent

🤖 Agent 通用知识（Prompt 与模型调用）

  • Agent 前半段负责收集上下文，后半段负责生成答案。
  • Prompt 是大模型真正接收到的输入。
  • PromptTemplate 用于规范 Prompt 格式。
  • Memory 通常需要摘要压缩后再进入 Prompt。
  • 模型调用层通常通过统一接口屏蔽供应商差异。
  • Model Routing 用于实现多模型切换与故障转移。
  • ChatClient 本质是模型 API 适配器。
  • Streaming 是现代 Agent 的标准能力。
  • SSE 是流式回答最常见的前后端通信方案之一。
