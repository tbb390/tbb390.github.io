📖 ragent大框架与streamchatpipeline
  • 全局架构理解
    • Ragent 前端：React + TypeScript + Vite，提供聊天界面和管理后台。
    • Bootstrap：主业务服务，包含 RAG、知识库、入库 Pipeline、用户/后台模块。
    • StreamChatPipeline：Agent 核心流水线，负责处理用户问题到 LLM 输出。
    • Memory：会话历史和摘要，存储在 PostgreSQL + Redis。
    • Retrieval：向量检索，支持 pgvector 和 Milvus。
    • MCP：工具服务，独立 MCP Server 提供 Weather、Ticket、Sales。
    • LLM + Prompt：通过 infra-ai 层统一调用模型（Qwen、DeepSeek、Ollama、BaiLian 等）。
    • Framework：提供基础能力，包括 Redis、RocketMQ、Trace、幂等、ID、异常处理、Sa-Token。
  • StreamChatPipeline 流水线概览
    • 主要阶段：
      • Memory → Rewrite → Intent → Guidance → System → Retrieval → Prompt → LLM → SSE
    • 阶段内部并行：
      • Memory：历史消息 + 摘要并发加载
      • Rewrite：拆分后的子问题并行改写
      • Intent：多个子问题并行意图识别
      • Retrieval：
        • KB检索内部并行（多知识库、多个子意图）
        • MCP工具调用内部并行（多个工具 + 参数抽取）
    • 短路机制：
      • Guidance：意图置信度低 → 短路 → SSE 返回澄清问题
      • System：命中 SYSTEM 意图 → 跳过 KB/MCP → 直接 LLM 生成答案 → SSE 返回
      • Retrieval：KB+MCP 都为空 → 短路 → SSE 返回空答或降级提示
    • Prompt 与 LLM 输出：
      • 如果 KB/MCP 有结果 → 汇总 KB Context + MCP Context → Prompt 编排 → LLM → SSE
      • System Intent 也会经过 Prompt + LLM → SSE，只是跳过检索
  • 第五步 System Intent
    • 作用：无需外部知识或工具即可回答问题
    • 流程：Memory → Rewrite → Intent → System → LLM → SSE
    • 例如：
      • 闲聊（你好、谢谢）
      • 常识性问题（TCP三次握手）
    • 仍然会经过 Prompt 和 LLM，只是跳过检索阶段
  • KB/MCP 并行处理
    • KB：多知识库/多collection/子问题并行检索 → 去重 → Rerank → KB Context
    • MCP：多工具并行调用 → 参数抽取 → MCP Context
    • 汇总：
      • KB+MCP 都为空 → SSE快速返回空答或降级提示
      • 有结果 → Prompt 编排 → LLM → SSE
  • 总结理解
    • StreamChatPipeline 主流程串行，但阶段内部可并行
    • 第四步 Guidance 和第五步 System 主要是条件判断和短路，不并行
    • 检索阶段（第六步）是真正的并行处理阶段，KB 和 MCP 可同时执行
    • 整个 Pipeline 可以理解成一个带条件分支和短路机制的状态流
    • 官方接入层 → 编排层（Pipeline） → 模型层（infra-ai LLM/Embedding/Rerank） → 数据层（PostgreSQL/Redis/Milvus/MCP Server）
💡计算机网络
  • DHCP（动态主机配置协议）
    • 作用：自动为主机分配 IP 地址、子网掩码、默认网关、DNS 等网络参数。
    • 工作流程：Discover（发现）→ Offer（提供）→ Request（请求）→ ACK（确认）。
    • 优点：减少手动配置，提高地址管理效率。
    • 重点理解：设备开机后能够自动获取 IP 并接入网络。
  • DNS（域名系统）
    • 作用：将域名解析为 IP 地址。
    • 例如：访问 www.example.com 时，DNS 负责找到对应服务器 IP。
    • 相当于互联网中的“电话簿”或“翻译器”。
    • 重点理解：用户记域名，计算机通过 IP 通信。
  • FTP（文件传输协议）
    • 作用：在客户端与服务器之间传输文件。
    • 支持文件上传、下载和管理。
    • 常用端口：21（控制连接）。
    • 重点理解：实现网络中的文件共享与传输。
  • HTTP（超文本传输协议）
    • 作用：浏览器与 Web 服务器之间传输网页数据。
    • 访问网站时主要使用 HTTP/HTTPS 协议。
    • 常用端口：80（HTTP）、443（HTTPS）。
    • 重点理解：网页访问本质上是浏览器与服务器之间的数据交换。
  • Trunk
    • 用于在一条物理链路上传输多个 VLAN 的数据。
    • 常见于交换机与交换机之间的连接。
    • 通过 VLAN 标签区分不同 VLAN 的数据帧。
    • 重点理解：一根网线承载多个 VLAN 的通信。
  • SVI（交换虚拟接口）
    • 是三层交换机上对应 VLAN 的虚拟接口。
    • 每个 VLAN 可以拥有自己的网关地址。
    • 用于实现不同 VLAN 之间的三层通信。
    • 重点理解：SVI 是 VLAN 的逻辑网关。
🤔agent
  • Agent 概念
    • Agent = LLM + Memory + Planning + Tool + Execution。
    • 能够自主完成任务，而不仅仅是回答问题。
  • Memory（记忆）
    • 保存历史对话和上下文。
    • 支持长期记忆和短期记忆。
  • Intent（意图识别）
    • 理解用户真正想做什么。
    • 决定后续执行方向。
  • Planning（任务规划）
    • 将复杂任务拆分为多个步骤。
    • 决定执行顺序和策略。
  • Routing（路由决策）
    • 根据任务选择知识库、工具或直接回答。
    • 属于 Agent 的决策能力。
  • Retrieval（知识检索）
    • 从外部知识库获取信息。
    • 解决大模型知识时效性问题。
  • Tool Calling（工具调用）
    • 调用外部 API、数据库或系统工具。
    • 扩展大模型能力边界。
  • Execution（任务执行）
    • 执行检索、工具调用或工作流。
    • 获取执行结果。
  • Reflection（反思）
    • 检查结果是否正确。
    • 必要时重新规划和执行。
  • Agent 基本流程
    • Memory → Intent → Planning → Routing → Retrieval/Tool → Execution → Reflection → Response
