二、计算机网络：IP 协议可靠吗？

今天首先复习了 IP 协议的基本特点。IP 协议本身属于尽力而为的网络层协议， 它主要负责数据包的寻址和转发，但不保证数据一定能够送达，也不保证数据一定按顺序到达。

因此，网络通信中的可靠性通常需要由更高层协议提供。例如 TCP 会在 IP 的基础上， 通过连接建立、确认机制、重传、流量控制等方式提供可靠传输。

应用层 ↓ TCP / UDP ↓ IP ↓ 数据链路层 ↓ 物理层

三、网络协议体系结构

复习了计算机网络的分层思想以及各层主要负责的功能。网络协议分层的核心目的， 是把复杂的网络通信过程拆分成不同层次，每一层负责相对明确的任务。

  • 物理层：负责比特流在物理介质上的传输。
  • 数据链路层：负责局域网中的帧传输和链路层通信。
  • 网络层：负责 IP 寻址和不同网络之间的路由。
  • 传输层：负责端到端通信，常见协议包括 TCP 和 UDP。
  • 应用层：为具体应用提供网络服务，例如 HTTP、DNS 等。

设备和层次之间也存在对应关系，例如路由器主要工作在网络层， 二层交换机主要处理数据链路层，而主机需要实现完整的网络协议栈。

四、TCP 与 UDP

TCP 是面向连接的可靠传输协议，能够提供连接管理、可靠传输以及流量控制等能力。 UDP 则是无连接协议，不保证数据一定到达，也不保证顺序，但协议开销相对更小。

  • TCP：面向连接、可靠传输、适合对数据完整性要求较高的场景。
  • UDP：无连接、尽力而为、传输开销较小，适合实时性或广播、多播等场景。

今天重点重新区分了“网络层 IP 提供尽力而为的传输”和“TCP 在传输层提供可靠性”这两个概念。

五、套接字与网络通信端点

Socket 可以理解为网络通信的端点。通常通过：

IP 地址 + 端口号

来标识一个具体的通信端点。IP 地址用于定位主机， 端口号则用于区分同一台主机上的不同应用程序。

同一台设备可以同时运行网页、聊天软件和游戏等多个网络程序， 不同程序可以通过不同端口进行通信。

六、DNS 与 NAT

DNS 主要解决域名和 IP 地址之间的转换问题。 用户通常更容易记住域名，而网络中的实际通信仍然需要通过 IP 地址进行定位。

NAT 是缓解 IPv4 地址不足的重要技术，通过私有地址与公网地址之间的转换， 使多个内部设备可以共享较少的公网 IP。

  • 静态 NAT：固定的一对一地址转换。
  • 动态 NAT：从公网地址池中动态分配地址。
  • PAT：通过端口号区分不同内部主机，共享同一个公网 IP。

七、IPv4 地址不足与 IPv6

IPv4 使用 32 位地址，能够提供的地址数量有限。 NAT 可以缓解地址不足的问题，但不能从根本上解决 IPv4 地址空间有限的问题。

IPv6 使用 128 位地址，提供了更大的地址空间， 从 IPv4 向 IPv6 迁移才是解决地址空间不足的长期方向。

八、分布式网络应用程序设计

继续复习了网络协议与分布式应用之间的关系。 分布式系统中的服务可以部署在不同的服务器、不同城市甚至不同地区， 但对用户来说通常仍然表现为一个完整的系统。

常见的网络应用架构包括：

  • C/S：客户端与服务器之间进行通信。
  • B/S：浏览器作为客户端，通过 HTTP 等协议访问服务器。
  • P2P：节点之间地位相对平等，可以直接进行资源交换。

同时理解了服务集群的基本思想：多个服务器可以共同处理请求， 提高系统的处理能力和可用性。

九、网络编程接口

从网络编程的角度复习了不同类型的 Socket。

  • 原始套接字：可以直接处理更底层的网络协议数据。
  • 流式套接字：通常基于 TCP，提供面向连接的可靠通信。
  • 数据报套接字：通常基于 UDP，采用无连接的数据报通信方式。

同时了解了网络开发和抓包相关的接口与工具基础，例如 Windows 网络驱动接口规范， 以及用于原始数据包捕获的 PCAP 类库。

十、计算机网络知识串联

今天的内容可以从一次网络访问过程串起来：

用户输入域名 ↓ DNS 解析得到 IP 地址 ↓ 应用程序通过 Socket 建立通信端点 ↓ 根据需求选择 TCP 或 UDP ↓ IP 协议负责网络层寻址和转发 ↓ 路由器根据网络层信息进行转发 ↓ 最终到达目标服务器

在更大的应用场景中，多个服务器又可以组成分布式系统或服务集群， 通过网络协议完成不同服务之间的数据交换。
