📚 教资科二：教育知识与能力

第四章：中学生心理发展与教育

1. 知觉的基本特征（理选体常）

  • 理解性： 人在知觉事物时，会根据已有知识经验进行理解和解释。
  • 选择性： 人在面对大量信息时，会主动选择自己关注的信息。
  • 整体性： 人能够将事物的各个部分综合起来，形成整体认识。
  • 恒常性： 即使知觉条件发生变化，人对事物的认识仍保持相对稳定。

2. 影响遗忘进程的因素（人才请发誓）

  • 材料性质： 不同类型材料的遗忘速度不同。
  • 学习程度： 学习越充分，记忆保持效果越好。
  • 时间因素： 遗忘一般表现为先快后慢的规律。
  • 情绪状态： 积极稳定的情绪有助于记忆保持。
  • 复习方式： 合理复习能够减少遗忘。
  • 识记材料数量： 材料数量越多，记忆难度越大。

3. 提高记忆能力的方法（多方经理组目的）

  • 多感官参与： 利用视觉、听觉等多种方式加强记忆。
  • 方法合理： 采用科学记忆方法，提高学习效率。
  • 及时复习： 根据遗忘规律进行复习巩固。
  • 理解记忆： 在理解基础上进行记忆。
  • 组织加工： 对知识进行分类整理，形成体系。
  • 目的明确： 明确学习目标，提高记忆积极性。

4. 影响问题解决的主要因素（原定动情验个孕）

  • 知识经验： 已有经验会影响问题解决方式。
  • 定势： 过去形成的习惯思维可能促进或阻碍问题解决。
  • 动机： 解决问题的动力影响解决效果。
  • 情绪： 积极情绪有助于思考，消极情绪可能造成阻碍。
  • 原型启发： 已有类似事物能够提供解决思路。
  • 个性因素： 个人能力、性格特点会影响问题解决。

5. 学生学习的特点（尖叫的系统班很被动）

  • 间接性： 学生主要通过学习已有知识经验获得发展。
  • 系统性： 学生学习具有计划性和组织性。
  • 接受性： 学生学习过程具有一定的被指导特点。
  • 被动性： 学生学习通常受到教学目标和教师安排影响。
  • 主动性： 有效学习仍需要学生主动参与。

💻 信创底层体系 + 操作系统与跨平台适配原理

信创基础学习，本质上是操作系统知识的进一步延伸。

底层连接：

  • CPU 架构
  • 驱动体系
  • 硬件交互

上层连接：

  • 数据库
  • 中间件
  • 运行环境
  • AI 推理服务
  • 智能体应用

该体系能够解释很多工程问题：

  • 为什么同一份源码换平台后需要重新编译。
  • 为什么 Python 包在 X86 架构可以安装，而 ARM 架构可能没有对应 whl。
  • 为什么 AI 推理框架、加速库和部署环境存在架构限制。

🏗️ 信创体系四层结构

  • 第一层：整体生态认识
    国产 CPU 架构、国产操作系统、国产基础软件生态。
  • 第二层：系统基础操作
    文件系统、文件管理、文本处理。
  • 第三层：系统运维能力
    用户权限、进程管理、磁盘管理、网络配置、软件包管理、systemd 服务、日志分析。
  • 第四层：系统能力与应用结合
    数据库部署、中间件运行、AI 推理服务部署、智能体应用运行。

🤖 技术栈分层与故障排查框架

完整技术体系可以划分为五层：

  • 硬件层： CPU、内存、硬盘、网卡、GPU、NPU、AI 加速芯片。
  • 系统层： 操作系统、内核、驱动。
  • 基础支撑层： 数据库、中间件、运行环境、容器环境。
  • AI 服务层： 推理引擎、模型服务、Agent 运行环境。
  • 业务应用层： 智能问答、RAG 系统、工具调用、行业应用。

故障排查流程：

硬件 ↓ 内核与驱动 ↓ 系统服务 ↓ 运行环境 ↓ 模型推理服务 ↓ 智能体执行 ↓ 业务逻辑

🖥️ 国产 CPU 与跨平台适配原理

国产 CPU 主要包括：

  • 飞腾、鲲鹏： ARM 架构。
  • 海光、兆芯： X86 架构。
  • RISC-V： 新兴开放架构。

不同指令集之间机器码不同， 即使都是 Linux 系统，也不能认为软件完全通用。

跨平台运行需要：

  • 获取对应架构的软件包。
  • 或者基于源码重新编译。
  • 保证依赖库、驱动、加速组件全部适配。

⚙️ 操作系统承上启下作用

操作系统位于硬件和应用之间。

  • 向下： 通过驱动管理 CPU、GPU、网卡、存储设备。
  • 向上： 通过系统调用、系统库和用户接口提供运行环境。

例如 Python 执行 open()：

Python 程序 ↓ 系统调用 ↓ Linux 内核 ↓ 权限检查 ↓ 文件系统 ↓ 磁盘驱动 ↓ 硬件设备

🔐 内核空间与用户空间

Linux 内核负责：

  • CPU 调度
  • 虚拟内存管理
  • 网络协议栈
  • 设备驱动
  • 进程管理

用户空间运行：

  • 普通应用
  • Python 程序
  • Java 程序
  • AI 服务

用户程序不能直接访问内核内存或操作硬件寄存器， 所有硬件访问必须通过系统调用完成。

用户空间与内核空间隔离保证了系统安全性、稳定性以及资源管理能力。

💡 收获 & 理解

今天最大的收获是理解了 AI 应用开发不仅依赖模型和框架， 底层操作系统、硬件架构以及运行环境同样决定系统能否稳定运行。

  • 智能体、RAG、工具调用等上层能力，本质依赖底层系统环境。
  • 理解操作系统和跨平台适配原理，可以帮助定位实际工程问题。
  • 模型部署不仅是调用 API，还涉及硬件、推理框架和系统优化。
